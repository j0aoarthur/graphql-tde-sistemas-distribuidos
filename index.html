01 O problema

Um recurso físico. Duas mãos.

Como alocar a viatura mais próxima exatamente uma vez, com centrais independentes e falhas parciais?

01

A central abre.

A resposta volta na hora, antes de qualquer alocação.

React + Apollo Client / JWT

02

O stream segura.

Se o despacho cai, o chamado fica retido — não se perde.

Redis Streams / consumer group

03

O lock decide.

Quem não obtém a posse vai para a próxima viatura.

NestJS + Prisma / SET NX PX

04 Decisões

Cada operação escolhe o seu lado.

Abrir ocorrência prefere disponibilidade. Alocar viatura prefere consistência.

Invariante explícita.Falha observável.Limite conhecido.
01

Prefere falhar a alocar duas vezes.

Sem posse do lock, recua. Não garante que o TTL cubra todo o trabalho.

SET NX PX 5000

02

Aceitar antes de entender.

Responde RECEBIDA na hora. Isso não afirma que houve despacho.

XADD stream:ocorrencias

03

Receber de novo. Gravar uma vez.

Idempotência na persistência, não promessa de entrega exactly once.

eventId · XACK

04

Falhar rápido para não falhar junto.

Circuit breaker contém a cascata, mas não repõe o serviço que caiu.

opossum · backoff 200/400/800ms

Equipe: João Arthur, Felipe Henriques, Raíssa Quezia e Yuri Rebouças. “SDV” é a identidade conceitual do trabalho, não um produto em operação. Nenhum dado real de segurança pública foi usado.

Guia técnico

  • Monorepo: gateway, ocorrencias-service, viaturas-service, painel-frontend e script de concorrência.
  • Database-per-service; o vínculo entre domínios é lógico, por UUID.
  • Síncrono por GraphQL Federation; assíncrono por Redis Streams com consumer group.
  • CI em GitHub Actions: lint, testes, build e imagem publicada só em main.
